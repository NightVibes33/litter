Quick troubleshooting

App will not connect to a server

Confirm the device and server are on the same network if you are using local discovery. If you are connecting remotely, verify the SSH host, port, username, and reachable network path. If the server was recently restarted, force a fresh connection instead of reusing a stale session.

Server does not appear in discovery

Local discovery depends on the server advertising correctly on the same LAN. Check Wi-Fi, VPN state, subnet differences, and whether discovery traffic is being filtered by the router or the host firewall.

Remote runtime or model list looks wrong

Disconnect and reconnect the runtime, then reopen the model picker. If one runtime is unhealthy, Alley Cãt may preserve cached state while retrying. Report which runtime you used and whether the problem is isolated to one backend.

Voice input is unavailable

Check microphone permission in iOS Settings, confirm the active runtime supports the voice path you expect, and retry on a stable connection. If the session closes immediately, note whether the failure happens before recording, during streaming, or when audio should start playing back.

Project or file browser is stuck

Refresh the current project view and retry after reconnecting the runtime. If the issue happens only on a remote runtime, include the directory you were opening and whether the runtime rejected a picker or file-list command.

TestFlight build will not install or launch

Verify you are on the latest available build in TestFlight, fully remove the previous app if the device kept an invalid beta state, then reinstall. If the build launches and exits, report the build number and whether the crash happens before or after the first screen appears.

Privacy, account, and data deletion

No account required

Alley Cãt does not require a hosted Alley Cãt account to use the app. It is designed to connect to runtimes and systems you control rather than route your work through a mandatory central service.

Delete local data

To remove app data stored on the device, delete the app from iPhone or iPad. This removes locally stored preferences and app documents from the device sandbox.

Delete credentials

If you configured SSH credentials, tokens, or saved connections, remove them inside the app first when possible, then delete the app if you want the remaining local state cleared.

Privacy questions

For privacy-specific questions or deletion requests tied to any support email you sent, contact NightVibes33@proton.me and reference the email address you used so the thread can be located.

Compatibility and expected behavior

Supported platforms
Alley Cãt is intended for iPhone and iPad builds distributed through TestFlight and the App Store.
Network behavior
Connection quality depends on your local network, SSH path, remote host availability, and the runtime you connect to.
Local-first behavior
Sessions, preferences, and connection flows are designed around device-local use and direct connections to systems you control.
Third-party dependencies
Some capabilities rely on remote runtimes, SSH, local network discovery, voice infrastructure, or external host availability. A runtime outage can look like an app bug, so include the runtime details in your report.

Frequently asked questions

How fast will I get a reply?

Support is handled by email and response time can vary. Critical install, launch, or account-access issues should include the exact subject line, version number, and reproduction steps so triage is faster.

Where should I send bug reports?

Email NightVibes33@proton.me. If the issue is public and reproducible, you can also reference or open an issue on GitHub.

What if a TestFlight build is rejected or expires?

Install the newest available build in TestFlight. If a build expires or is pulled, wait for the replacement build and include the expired build number in any support email so the report maps to the right release cycle.

Can you troubleshoot my runtime or server setup?

Support can help isolate whether the issue is likely in the app, the connection path, or the target runtime. Include host type, connection method, and the exact step where the runtime stops responding.
